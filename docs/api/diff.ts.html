diff_hunks_parse
#

diff.ts view source

(patch: string): Result<{ value: DiffHunk[]; }, DiffHunksParseError> import {diff_hunks_parse} from '@fuzdev/fuz_util/diff.js';

Parses one file's unified diff as git prints it (git diff -U3, or any context width) into hunks — for rendering a change from the patch alone, without either side's text.

File header lines before the first @@ (diff --git, index, ---, +++, mode, rename, and copy lines) are skipped; a patch with headers and no hunks (a rename or mode change alone) or empty text parses to []. A count omitted from a @@ header is 1, and the section text after the closing @@ is ignored. \ No newline at end of file sets no_newline on the line before it, per DiffLine. Lines split on \n only, so \r stays in line text as in diff_lines.

The result is checked against itself: each hunk's lines must match its header's counts, hunks must be in order and not overlap, the unchanged runs between hunks must be equally long on both sides, each hunk must change a line, no line or hunk may follow a side's no-newline line, and no empty line may be marked no-newline. A failure's kind tells a binary patch from malformed text.

Inside a hunk an empty row is an empty unchanged line, as git prints one under diff.suppressBlankEmpty (and git apply and GNU patch accept). The patch must be plain exact-text output, as diff_lines_from_edits details: --no-textconv --no-ext-diff, no color, no --word-diff (its rows carry no line markers, so they mostly parse as a hunk that changes nothing, which is refused), and no option that ignores whitespace or lines (-w, -b, --ignore-blank-lines, and the like), under which a context line shows one text for lines that differ between the sides. git diff -D prints a deleted file's headers with no hunks, so it parses to [] like a pure rename.

patch

one file's unified diff text

type string

returns

Result

the hunks, with starts and counts as their headers give them

diff_lines_from_edits
#

diff.ts view source

(a: string, b: string, edits: DiffEdit[]): Result<{ value: DiffLine[]; }, { message: string; }> import {diff_lines_from_edits} from '@fuzdev/fuz_util/diff.js';

Rebuilds a whole-file line diff from two texts and their change regions — the Array<DiffLine> that diff_lines(a, b) returns when its diff chose these regions. Lets a caller render another differ's choices, like git's histogram diff from git diff -U0 headers, without the line text crossing a wire.

Lines split as in diff_lines, so a terminated and an unterminated final line never match: git reports a newline-only change as a region holding the final line, and that region's lines carry no_newline. Each region emits its removes before its adds; the lines between regions are same. Edits that touch (no unchanged line between them on either side) merge into one region, as diff_lines normalizes a run of changes. An empty edits asserts the texts are equal.

Inconsistent input is an expected failure, not a bug — stale edits or the wrong blob — so it returns a failed Result naming the edit or line: numbers that aren't non-negative integers, an edit that changes no lines, edits out of order or overlapping, a region past either text's end, unchanged runs of different lengths on the two sides, or an unchanged line whose text (or final newline) differs between the sides.

The edits must come from an exact-text diff of these same texts: with git, --no-textconv --no-ext-diff, no color or --word-diff, no option that ignores whitespace or lines (-w, -b, --ignore-space-at-eol, --ignore-cr-at-eol, --ignore-blank-lines, -I), and blobs or commits rather than a worktree file that clean/smudge filters or core.autocrlf change. Under an ignoring option git calls lines unchanged whose text differs, which a same DiffLine can't hold, so such edits are refused.

type string

b

type string

DiffEdit

import type {DiffEdit} from '@fuzdev/fuz_util/diff.js';

One change region as a @@ header numbers it, [a_start, a_count, b_start, b_count] — the line-text-free form of a diff that git diff -U0 headers carry. Starts are 1-based; a side with a zero count starts at the line *before* the region on that side, 0 at the very beginning, as in DiffHunk. A count omitted from a header is 1.
